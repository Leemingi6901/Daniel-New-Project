## 1. 왜 만들었나

IT Ops의 하루는 기록보다 요청이 빠르다. 복도에서, 메신저로, 회의 중에 받은 요청은 적지 않으면 사라진다. 고과 시즌에는 반년 치 기억을 되짚어야 한다. 그래서 세 가지를 목표로 잡았다.

| 목표 | 어떻게 |
|---|---|
| **누락 방지** | 슬랙에서 `/add` 한 줄로 바로 등록. 매일 아침 업무 일보가 마감 지난 일·오늘 마감·놓친 반복 업무를 먼저 알려 준다. |
| **고과 증적** | 완료한 업무가 쌓이면 마감 준수율, 처리 기간, 장애 대응, 부서별 지원 건수가 반기·연간 성과 요약으로 자동 집계된다. |
| **멈추지 않는 기록** | 하루 두 번 GitHub에 전체 백업. 서비스가 멈춰도 명령 두 줄이면 어느 PC에서나 다시 띄운다. |

### 하루가 이렇게 흘러간다

| 시각 | 무슨 일 | 누가 |
|---|---|---|
| 08:00 | 어제 끝낸 업무를 보관함으로 옮겨 대시보드엔 할 일만 남김 | 자동 |
| 09:07 | **업무 일보** 도착: 어제 한 일, 마감 지남·오늘 마감, 일정, 반복 업무, 입·퇴사, 라이선스 만료. 금요일엔 주간 요약도 | 슬랙 |
| 수시로 | `/add 물류센터 VPN 계정 발급 금요일까지 #지원` 처럼 말하듯 등록, 끝나면 버튼으로 완료 | 나 |
| 13:07 | **회의 알림**: "53분 후 회의 · 7층 소회의실 · IT Ops 4명" | 슬랙 |
| 17:00 | **반복 업무 확인**: 아직 안 한 것만 완료 버튼과 함께. 다 했으면 안 옴 | 슬랙 |
| 00:17 · 12:17 | GitHub 비공개 저장소에 날짜별 전체 백업. 비어 있는 백업은 거부 | 자동 |

## 2. 대시보드 — 열면 지금 할 일부터

오늘의 회의, 마감 지난 일, 오늘 마감을 급한 순서로 모아 보여 준다. 무엇부터 할지 고민하는 시간을 줄이는 게 목적이다.

- **지금 처리할 것:** 회의 → 마감 지남 → 오늘 마감 순으로 묶고, 회의는 "4시간 51분 후"처럼 남은 시간을 센다.
- **빠른 등록:** 한 줄 쓰고 Enter. 자세한 양식은 `N` 키.
- **오늘의 반복 업무:** 맨 위 띠에서 바로 체크. 매일·N일마다·요일·매월 주기.
- **통합 검색:** `Ctrl K`로 업무·일정·메모·매뉴얼을 한 번에.
- **라이트·다크 모드**, 글꼴 4종.

![모바일 대시보드](/wiki/task-tracker/m-dashboard.jpg#narrow)

*휴대폰에서도 같은 기능. 하단 메뉴와 엄지 위치의 새 업무 버튼, 홈 화면 앱(PWA)으로 설치한다.*

## 3. 업무 관리 — IT Ops 업무 모양 그대로

보안·인프라·IT 지원은 적어야 할 내용이 다르다. 분류를 고르면 그에 맞는 칸이 나온다.

![새 업무 입력](/wiki/task-tracker/taskmodal.jpg)

| 분류 | 입력 항목 | 이렇게 쓰인다 |
|---|---|---|
| 보안 · 인프라 | 장비·솔루션(등록 목록에서 선택), 장애/작업 구분, 장애 보고서(발생·복구 시각, 영향, 원인, 조치, 재발 방지) | 장비별 장애 건수, 평균 복구 시간 |
| IT 지원 | 요청 부서, 요청자, 지원 유형(계정·권한, PC·장비, 네트워크·VPN 등 9종) | 부서별·유형별 지원 통계 |
| 공통 | 체크리스트, 결과 메모, 진행 기록(상태 변경 자동 기록) | 성과 요약의 주요 업무 목록 |

반복되는 일과 기한이 있는 일은 따로 챙긴다.

![입·퇴사 체크리스트](/wiki/task-tracker/lifecycle-open.jpg)

*입·퇴사 체크리스트: 입사일 기준 D-5부터 D+7까지 할 일이 날짜에 맞춰 자동으로 생긴다. 이름은 이니셜로만 적는다.*

![라이선스·인증서](/wiki/task-tracker/licenses.jpg)

*라이선스·인증서: 만료 D-day, 연간 비용 합계, 30일 안 만료 알림.*

![반복 업무](/wiki/task-tracker/recurring.jpg)

*반복 업무: 주기를 정하면 해당하는 날 대시보드와 알림에 올라온다.*

그 밖에 메모 게시판(중요·인수인계 태그, 고정), 사용자용 매뉴얼(마크다운, PDF로 배포), 캘린더 구독(구글·아이폰 캘린더에 마감과 일정 표시)이 있다.

## 4. 슬랙 알림 — 앱을 열지 않아도 먼저 알려 준다

아래 메시지는 예시 데이터로 **실제 알림 코드가 만든 결과 그대로**다.

![슬랙 업무 일보](/wiki/task-tracker/slack-daily.jpg#narrow)

*평일 아침 업무 일보. 월요일에는 금~일요일에 한 일을 모아 보여 준다.*

![슬랙 반복 업무·회의·주간 알림](/wiki/task-tracker/slack-side.jpg#narrow)

*17시 반복 업무 알림(버튼으로 바로 체크), 회의 알림, 금요일 주간 요약.*

| 알림 | 보내는 때 |
|---|---|
| 업무 일보 | 평일 출근 후 첫 확인(09시대) |
| 주간 요약 | 금요일, 일보와 함께 |
| 반복 업무 | 17시대, 남은 것만 |
| 회의 | 시작 60분 전 안쪽 |

**같은 알림은 딱 한 번.** 알림마다 고유한 기록을 먼저 잡고(claim) 보내기 때문에 두 번 호출되거나 다시 시도해도 중복으로 오지 않는다. 보내기에 실패하면 15분 뒤 다시 보낸다. 받을 곳은 슬랙·텔레그램 중에 고른다.

## 5. 명령어 — 말하듯 쓰면 업무가 된다

슬랙(또는 텔레그램)에서 봇에게 보내면 바로 처리된다. `/help`를 보내면 이 안내가 그대로 나온다.

| 명령어 | 하는 일 |
|---|---|
| `/add 내용` | 업무 등록. 글에서 마감·분류·우선순위를 읽어 낸다 |
| `/memo 내용` | 메모 게시판에 저장. 첫 줄이 제목 |
| `/today` | 오늘 볼 것: 마감 지남·오늘 마감, 일정, 반복 업무. 남은 반복 업무는 버튼으로 체크 |
| `/list` | 진행 중 업무를 마감 가까운 순으로. 버튼을 누르면 완료 |
| `/done 이름` | 오늘 반복 업무 체크 또는 업무 완료. 이름 일부만 써도 찾고, 여러 개면 버튼으로 고른다 |
| `/help` | 명령어 안내 |
| (그냥 보내기) | "업무로 등록 / 메모로 저장" 버튼으로 묻는다 |

![슬랙 명령어 대화](/wiki/task-tracker/slack-commands.jpg#narrow)

- 누른 버튼은 메시지에서 사라지고 처리 결과가 한 줄 붙는다. 같은 버튼을 두 번 누를 일이 없다.

## 6. 보고서와 성과 요약 — 쌓인 기록이 그대로 보고서로

따로 정리하지 않아도 일일·주간·월간·장애 보고서와 반기 성과 요약이 만들어진다. 마크다운 복사와 PDF 저장을 지원한다.

![성과 요약](/wiki/task-tracker/performance.jpg)

*성과 요약(반기·연간): 한 줄 요약과 핵심 지표, 월별 추이, 분류별 완료, 주요 업무.*

![월간 보고서](/wiki/task-tracker/monthly.jpg)

*월간 보고서: 전월 대비, 장비·솔루션별 현황, 부서별 IT 지원.*

![기록 잔디](/wiki/task-tracker/heatmap.jpg)

*기록 잔디: 완료한 업무와 반복 업무 체크를 하루 단위로. 연속 기록과 가장 많이 한 날.*

| 성과 지표 | 계산 방법 |
|---|---|
| 마감 준수율 | 마감일이 있는 완료 업무 중 마감일 안에 끝낸 비율 |
| 평균 처리 기간 · 당일 처리율 | 시작일부터 완료일까지의 날 수 |
| 반복 업무 수행률 | 해야 했던 횟수 대비 체크한 횟수. 진행 중인 반기는 오늘까지만 센다 |
| 장애 대응 | 건수, 평균 장애 시간, 보고서 작성률 |

## 7. 구성과 안정성 — 작게 만들고, 멈추지 않게

모든 구성 요소가 무료 플랜 안에서 돈다. 어느 한 곳이 멈춰도 기록은 남고 다시 띄울 수 있게 했다. 자세한 규칙은 [9탄 설계 문서](/wiki/web/task-tracker-architecture)에 있다.

![구성도](/wiki/task-tracker/architecture.jpg)

- **알림은 한 번만:** 15분마다 "보낼 알림이 있나" 확인. 시간대 확인 → 보냈나 확인 → 기록 선점 → 발송. 보낼 시간대가 아니면 DB도 깨우지 않는다.
- **백업은 세 겹:** 하루 두 번 날짜별 저장, 0건 백업 거부, 30% 넘게 줄면 경고, 복구할 때 빈 백업은 건너뜀.
- **어디서든 다시:** Vercel이 멈춰도 새 PC에서 `npm run restore` → `npm run dev:local` 두 줄. 비밀값 파일 없이 실제로 시험해 확인했다.

| 서비스 | 역할 | 무료 한도와 사용량 |
|---|---|---|
| Vercel | 화면·API, 하루 한 번 크론 | Hobby 플랜. 푸시하면 자동 배포 |
| Neon | Postgres 데이터베이스 | 월 100 CU-시간. 밤에는 쉬도록 설계 |
| GitHub | 코드, 백업, 백업 자동화 | Actions 월 2,000분 중 약 60분 |
| cron-job.org | 15분마다 알림 확인 호출 | 무료, 실패 시 메일 알림 |
| Slack · Telegram | 알림, 명령어 | 무료 (데이터는 앱에 있어 90일 제한과 무관) |

## 8. 보안 — 나만 쓸 수 있게

혼자 쓰는 도구라 사용자 관리 대신, 들어오는 길마다 다른 열쇠를 둬서 "나만" 쓸 수 있게 했다.

| 들어오는 곳 | 확인 방법 |
|---|---|
| 웹 화면 | 비밀번호 로그인, httpOnly 세션 쿠키. 틀리면 응답을 늦춰 대입 공격을 느리게 |
| 슬랙 | 요청 서명(HMAC) 확인, 5분 넘은 요청 거절, 내 계정에서 온 것만 처리 |
| 텔레그램 | 봇 토큰에서 만든 비밀 헤더 확인, 내 채팅에서 온 것만 처리 |
| 알림 확인 호출 | 알림 전용 키. 이 키로는 백업 등 다른 기능을 부를 수 없다 |
| 캘린더 구독 | 주소에 들어간 비밀 토큰 |

**입력 원칙.** 비밀번호·접속 정보, 내부 IP·정책 상세, 고객 정보는 적지 않는다. 입·퇴사자는 이니셜로. "VPN 계정 발급 완료", "정책 42건 정리"처럼 결과만 기록한다.

## 9. 시작하기

1. **로그인하고 출근 시각 정하기** — 환경설정에서 출근 시각, 테마, 글꼴.
2. **장비·솔루션과 반복 업무 등록** — 담당 장비와 매일·매주 챙길 일을 넣어 두면 보고서와 알림이 바로 동작한다.
3. **슬랙 연결** — 개인 워크스페이스에 봇을 설치하고 키 세 개를 넣으면 다음 날 아침부터 업무 일보가 온다.
4. **요청이 오면 `/add`** — 자리에 없을 때 받은 요청도 그 자리에서 등록.
5. **반기 말에 성과 요약 열기** — 숫자와 주요 업무가 정리된 보고서를 마크다운이나 PDF로 가져간다.
