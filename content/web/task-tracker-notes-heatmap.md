[5탄](/wiki/web/task-tracker-git-deploy-templates)에서 push만 하면 배포되는 흐름을 만들었다. 이번엔 쓰면서 아쉬웠던 것 세 가지를 손봤다. 대시보드에서 혼자 튀던 반복 업무 바, 업무로 등록하기 애매한 메모를 둘 곳, 그리고 "그동안 얼마나 했나"를 한눈에 보는 화면이다.

## 반복 업무 바: 검정에서 테마 색으로

대시보드 맨 위의 "오늘의 반복 업무" 바는 검은 띠였다. 눈에는 확 띄었지만, 따뜻한 아이보리 팔레트 사이에서 혼자 이질적이었다. 바탕을 포인트 초록을 옅게 깐 색으로 바꾸고, 체크박스·완료 표시·닫기 버튼도 전부 테마 토큰으로 옮겼다.

```tsx
<div className="rounded-xl border border-[var(--accent)]/25 bg-[var(--accent)]/8 text-[var(--text-primary)]">
```

색을 직접 적지 않고 `var(--accent)`에 투명도만 주니까, 다크 모드에서도 따로 손대지 않아도 어두운 초록으로 따라간다.

## 메모 게시판

인수인계받은 내용이나 "나중에 꼭 기억해야 할 것"은 업무가 아니다. 완료할 일이 아니라서 업무로 등록하면 완료 이력과 리포트 숫자가 오염된다. 그래서 **업무와 완전히 분리된 저장소**를 따로 만들었다.

```ts
export interface Note {
  id: string;
  title: string;
  body: string;
  tag: "중요" | "인수인계" | "메모";
  pinned: boolean;
  createdAt: string;
  updatedAt: string;
}
```

4탄에서 만든 `Collection` 인터페이스 덕에 저장소 쪽은 템플릿 때처럼 거의 공짜였다. Blob 구현, Postgres 테이블(마이그레이션 `0002`), 이관 스크립트 한 줄, PGlite 테스트가 같은 틀로 붙는다. 알림·캘린더·CSV 쪽 코드는 업무 모듈만 보기 때문에, 메모가 거기 섞일 일이 구조적으로 없다.

### 고정은 "수정"이 아니다

목록은 고정한 글이 먼저, 그다음 최근 수정 순이다. 여기서 한 가지 걸렸다. 고정 버튼을 누를 때 수정 시각까지 갱신하면, 고정을 풀었을 때 그 글이 엉뚱하게 맨 위로 올라온다. 내용을 바꾼 게 아니니까 정렬 기준도 건드리지 않게 했다.

```ts
const contentChanged = input.title !== undefined || input.body !== undefined || input.tag !== undefined;
if (contentChanged) note.updatedAt = new Date().toISOString();
```

테스트에도 "고정은 수정 시각을 바꾸지 않는다"를 한 줄로 박아뒀다.

### 게시글처럼 읽고 쓰기

- 글을 누르면 먼저 **읽기 화면**이 뜨고, 수정은 버튼을 눌러야 들어간다. 인수인계 글은 쓰는 것보다 다시 읽는 일이 훨씬 많다.
- 본문의 URL은 링크로 바꿔 보여준다. 인수인계 글엔 문서 주소가 자주 들어간다.
- "복사" 버튼은 제목과 본문을 한 번에 클립보드로 복사한다. 메신저로 넘길 때 쓴다.
- 쓰던 내용이 있는데 창을 닫으면 확인 창을 띄운다. 긴 글을 날리는 게 제일 억울하다.
- 삭제는 다른 곳처럼 5초 되돌리기다.

### 포커스가 엉뚱한 버튼에 남는 문제

테스트하다가 이상한 걸 발견했다. 읽기 화면에서 "수정"을 누르고 바로 타이핑하면 글자가 아무 데도 안 들어갔다. 원인은 두 가지가 겹친 것이었다.

1. 모달은 **열릴 때만** 첫 입력칸에 포커스를 준다. 읽기 → 수정은 모달이 새로 열리는 게 아니라 안의 내용만 바뀌는 거라 이 로직이 돌지 않는다.
2. React는 같은 위치의 같은 종류 요소를 재사용한다. 방금 누른 "수정" 버튼 자리에 편집 화면의 "저장" 버튼이 그대로 재사용되면서 **포커스가 저장 버튼에 남아 있었다.**

2번은 꽤 위험하다. 이 상태에서 스페이스를 치면 저장 버튼이 눌린다. 수정 모드로 바뀔 때 제목 칸으로 포커스를 직접 옮기고, 커서를 끝에 두도록 고쳤다.

```ts
useEffect(() => {
  if (!editing || !current) return;
  const input = titleRef.current;
  input?.focus();
  input?.setSelectionRange(input.value.length, input.value.length);
}, [editing, current]);
```

### 메뉴가 다섯 개가 되면서

상단 메뉴에 "메모"가 추가되자 태블릿 폭(768px)에서 헤더가 30px 넘쳤다. 그 구간에서만 "새 업무" 버튼을 + 아이콘으로 줄였다. 모바일 하단 바는 "이력 / 반복"처럼 짧은 이름을 따로 두어 375px 화면에 들어가게 했다. 상단 검색(Ctrl+K)에도 메모 제목과 본문이 걸리게 했다.

## 기록 잔디

리포트 페이지에 깃허브 잔디 같은 1년치 기록 화면을 붙였다. 날짜별로 **완료한 업무 + 반복 업무 체크** 수를 세서 진하기로 칠한다.

### 날짜는 로컬 기준으로

제일 먼저 확인한 건 날짜 키다. `toISOString().slice(0, 10)`은 UTC라서, 한국 시간 새벽 1시에 끝낸 업무가 **전날 칸**에 찍힌다. 로컬 날짜로 키를 만들고, 이걸 테스트로 고정했다.

```ts
export function dateKey(d: Date): string {
  const y = d.getFullYear();
  const m = String(d.getMonth() + 1).padStart(2, "0");
  const day = String(d.getDate()).padStart(2, "0");
  return `${y}-${m}-${day}`;
}

// 테스트: KST 09-29 01:30 완료분은 09-29로 센다
assert.equal(dateKey(new Date("2026-09-28T16:30:00Z")), "2026-09-29");
```

### 색은 한 가지, 구간은 고정

양을 나타내는 색은 여러 색을 쓰지 않고 포인트 초록 **한 가지의 진하기**로만 나눴다. 테마 배경과 섞는 `color-mix`를 써서, 다크 모드에서도 같은 단계 구조가 유지된다.

```ts
const LEVEL_COLOR = [
  "var(--bg-elevated)",
  "color-mix(in oklab, var(--accent) 30%, var(--bg-elevated))",
  "color-mix(in oklab, var(--accent) 52%, var(--bg-elevated))",
  "color-mix(in oklab, var(--accent) 76%, var(--bg-elevated))",
  "var(--accent)",
];
```

진하기 구간은 최댓값 비율 대신 1 / 2 / 3~4 / 5+로 **고정**했다. 혼자 쓰는 앱이라 하루 건수가 작은데, 비율로 나누면 유난히 바빴던 하루 때문에 나머지 날이 전부 흐려진다.

### 연속 기록

"현재 연속"은 오늘 아직 아무것도 안 했어도 어제까지 이어졌으면 끊지 않는다. 아침에 리포트를 열 때마다 연속 0일이 뜨면 김이 샌다.

```ts
for (let i = sorted.length - 1; i >= 0; i--) {
  const d = sorted[i];
  if (d.total > 0) current += 1;
  else if (d.date === todayKey && current === 0) continue; // 오늘은 아직 진행 중
  else break;
}
```

### 칸을 누르면 그날 리포트로

잔디 칸을 누르면 아래의 일간 리포트가 그날로 이동한다. 방향키로 칸을 옮기고 Enter로 열 수도 있다. 칸 371개가 전부 Tab 순서에 들어가면 지옥이라, 한 칸만 Tab을 받고 나머지는 방향키로 옮기는 방식(roving tabindex)으로 했다.

과거 날짜로 이동할 수 있게 되자 기존 리포트의 오래된 문구가 드러났다. 1월 9일을 보고 있는데 "**오늘** 업무 6건을 끝냈어요", 버튼은 "← 어제"였다. 오늘이 아니면 "이날", 버튼은 "전날 / 다음날"로 바꿨다. 모바일에서 "일간" 버튼이 "일 / 간"으로 두 줄로 쪼개지던 것도 이참에 고쳤다.

### 모바일

53주 × 14px이면 약 740px이라 휴대폰에선 가로 스크롤이 생긴다. 처음 열 때 **오른쪽 끝(최근)**이 보이게 스크롤을 옮기고, 요일 이름 열은 `position: sticky`로 왼쪽에 붙여 스크롤해도 "월 / 수 / 금"이 사라지지 않게 했다.

## 마무리

이번엔 기능보다 **이미 있는 데이터를 다르게 보여주는 작업**이 많았다. 잔디는 새 데이터 없이 완료 기록만으로 그렸고, 메모는 기존 저장소 틀을 그대로 재사용했다. 한 가지 남은 한계는 반복 업무 체크 기록이 90일만 보관된다는 점이다. 그래서 잔디의 오래된 칸에는 완료한 업무만 반영된다. 없는 것보다는 낫다.
